# Review, master, 2026-10-11

**Reviewed by**: Muse Spark 1.3 (author on same model family; fresh context only, extra skepticism applied)
**Scope**: 19 files, uncommitted (package.json one-liner ignored as out of scope)
**Verdict**: Changes requested

## Summary

Spec 0007 replaces the demo socket map with stay/kitchen rooms, cookie-verified joins, server-only order fanout, extended LRU budgets, and a uniform 429 shape. Overall quality is high: auth gates are complete with proxy.ts parity, no secrets leak into logs or payloads, and the prove walk plus 30 passing vitest tests back the change. The two majors are a test-adequacy gap over the largest new security surface (socket joins) and a listener leak in the browser client; neither contradicts the spec, but both will bite soon.

## Major

### 🟠 Socket join auth and rate logic has no runner coverage, `server.ts:157`
**Problem**: The ~70 lines of join gating (IP budget, stay/account budget, probe budget, stay liveness, staff role/disabled/locked checks) are the security boundary of this feature, yet no vitest file exercises them. Coverage comes only from `scripts/prove-realtime.ts`, which needs `next build` plus a live database and is not in the test runner.
**Why it matters**: Per the test-adequacy bar, untested security-relevant branching is a Major. A future edit to `resolveStay`/`resolveStaff` or a budget key can regress silently; CI stays green.
**Suggested fix**: Extract the pure decision parts (probe-key selection, deny-code mapping, budget key choice) into a testable module, or add a socket-level integration test with mocked `prisma`/`auth` behind the existing `setRealtimeServer`-style seam.

### 🟠 `disconnect()` leaks the document visibility listener, `lib/realtime-client.ts:116`
**Problem**: `connect()` adds an anonymous `visibilitychange` listener on `document` that `disconnect()` never removes (only the `window` focus/online listeners are removed, and the anonymous closure cannot be referenced for removal). Every connect/disconnect cycle leaves one more document-level listener holding a stale closure.
**Why it matters**: In an SPA with repeated mount/unmount, each tab-visible event fires N accumulated `onFocus` handlers, each emitting a join and a REST refetch. Duplicate joins, duplicate refetches, and growing memory use.
**Suggested fix**: Name the visibility handler (like `onFocus`/`onOnline`) and remove it in `disconnect()`.

## Minor

### 🟡 Every denial fires `onJoinDenied` twice, `server.ts:142`
**Problem**: `answer()` both invokes the ack callback and emits `JOIN_DENIED`, and the client wires both paths to `onJoinDenied` (`lib/realtime-client.ts:68`, `lib/realtime-client.ts:99`). One denial therefore calls the screen's handler twice.
**Why it matters**: Duplicate denied-UI (double toast, double counter) on every rate-limited or forbidden join.
**Suggested fix**: Pick one channel: ack-only for solicited joins, event-only for server-initiated denies, and document the choice.

### 🟡 Deny logs print client IP outside the spec allowlist, `server.ts:159`
**Problem**: Spec 0007 allows log fields of stay plus order plus socket ids plus role only, but deny lines log `ip=${ip}` in four places.
**Why it matters**: Either the code violates AC-8's letter or the spec allowlist is wrong; both cannot stand. IP is low-sensitivity but the redaction contract must be exact.
**Suggested fix**: Amend the spec's log allowlist to include IP for limit denies, or drop IP from the log lines.

### 🟡 `parseCookies` throws on malformed cookie input, `server.ts:61`
**Problem**: `decodeURIComponent` throws `URIError` on inputs like `Cookie: %`, and the call sits unguarded in the connection handler.
**Why it matters**: Any client can send a malformed cookie header; the resulting throw is at best a dropped socket with a noisy error, at worst an unhandled exception in the connection path.
**Suggested fix**: Wrap the decode per-cookie in try/catch and skip undecodable pairs.

### 🟡 Shared debounce can skip post-reconnect refetch; no retry on failure, `lib/realtime-client.ts:53`
**Problem**: `lastRefetch` is shared across focus and reconnect reasons, so a focus refetch within 5s suppresses the reconnect refetch that heals a drop. The spec also names up to 3 tries with backoff plus jitter, but a failed `refetch()` is attempted once and dropped.
**Why it matters**: Stale screens after reconnect, and a single failed REST read during a reconnect storm leaves the gap unhealed.
**Suggested fix**: Track focus and reconnect debounce separately, and retry a failed reconnect refetch with backoff as the spec describes.

### 🟡 Emit helper doc contradicts its throw behavior, `lib/realtime-server.ts:6`
**Problem**: The header comment says helpers "validate the payload and report false instead of throwing", but `buildOrder*` throws on invalid input before any `live` check, and tests assert the throw.
**Why it matters**: Future route handlers calling emit after a REST commit will turn a validation bug into a 500 after a successful write unless they wrap in try/catch; the contract must say which.
**Suggested fix**: Correct the comment to state validation throws and no-server returns false, and note the call-after-commit try/catch obligation for slices 7/8.

### 🟡 Security-critical hashing and cookie name duplicated in `server.ts`, `server.ts:84`
**Problem**: `hashStayToken` and the `stay_session` literal reimplement `features/stay-session` (`stay-session.service.ts:23`, `:44`) instead of importing the canonical definitions, even though `server.ts` already imports from `./lib/*`.
**Why it matters**: Works today (prove walk passes), but any algorithm or cookie-name change in the canonical module silently breaks all socket joins with no shared test to catch it.
**Suggested fix**: Import `hashStayToken` and `STAY_COOKIE` from the stay-session feature module.

### 🟡 Per-key hit arrays grow unbounded inside the window, `lib/rate-limit.ts:25`
**Problem**: `hitRateLimit` pushes unconditionally; a hammering key accumulates one timestamp per attempt for the full 15 minutes with no cap.
**Why it matters**: An attacker can inflate memory per key far beyond the budget number; the LRU caps key count but not per-key array length.
**Suggested fix**: Cap stored timestamps per key (e.g. stop recording past a multiple of max) since over-budget precision needs only the oldest hit.

### 🟡 Debug leftovers in rate-limit test, `lib/rate-limit.test.ts:31`
**Problem**: `console.log(hitRatetest)` plus oddly named double-hit locals (`hitRate`, `hitRatetest`) committed to the test; the extra hit also mutates shared limiter state opaquely.
**Why it matters**: Noisy test output hides real signal; the test reads as unfinished.
**Suggested fix**: Remove the log line and assert the two sequential hits explicitly.

## Nits

- ⚪ `app/api/auth/[...all]/route.ts:58`, budget derived by `startsWith("signin:acct")` prefix sniff; pass the max alongside the key instead.
- ⚪ `lib/rate-limit.ts:93`, `takeBudget` exists to fuse probe-plus-record but neither `server.ts` nor the routes use it; use it at one call site or remove it.
- ⚪ `app/api/stay-session/mint/route.ts:54`, missing/invalid stay ids share one `"unknown"` bucket, so unrelated callers throttle each other; key by something caller-specific or skip recording there.

## Strengths

- `resolveStaff` in `server.ts:114` mirrors `proxy.ts` exactly (role, disabled, must-change, lockedUntil), closing the edge-vs-socket gate divergence I specifically probed for.
- 429 shape tests assert code plus `retryAfter` plus `Retry-After` header plus no id echo on both routes, locking AC-6/AC-8 against regression.
- Client-emitted order events are ignored and logged with socket id only, never rebroadcast; the prove script asserts the negative.
- Single-instance limits, spoofable-IP caveats, and the revoke fast-path gap are stated in spec Consequences and code comments rather than hidden.

## Test coverage

30/30 vitest tests pass across the six feature test files. Covered: room naming, payload shape and validation, fanout rooms and event names, client join/refetch/resync wiring, LRU budgets with retry timing, 429 shape and secret-echo on both REST routes. Not covered: the socket join decision tree in `server.ts` (only the manual `prove-realtime.ts` walk, which needs build plus database and is not in the runner), order fanout end-to-end (deferred to slice 7 by spec), and failure paths of `refetch` in the browser client.
